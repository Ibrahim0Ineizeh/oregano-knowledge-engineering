# Publish and archive

Upload the **contents of `public-release/`**, so `README.md` sits at the repository root. Do not upload the surrounding original assessment folders. If using the ZIP, extract it before uploading; placing only the ZIP in the repository would hide the organized report and notebook from the repository homepage.

1. Create a GitHub repository, for example `oregano-knowledge-engineering`, and choose **Public**.
2. Upload or push the package contents. Use a description such as: “An exploratory OREGANO knowledge graph study, from ontology construction to Bayesian compound ranking.”
3. Check the README images, report, PDF, and notebook on GitHub. Download the repository once and check that `visualizations/index.html` opens locally.
4. When the content is final, open repository **Settings**, find **Danger Zone**, and choose **Archive this repository**. Archiving makes the repository read-only; it remains available to view and can be unarchived later. [GitHub's archiving instructions](https://docs.github.com/en/repositories/archiving-a-github-repository/archiving-repositories).

The original approximately 820 MiB OWL file exceeds GitHub's ordinary 100 MiB per-file limit. The package excludes it and records regeneration instructions instead. [GitHub's large-file documentation](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github).

The README describes this as an archival edition prepared for publication. GitHub's actual archived status is applied only in repository settings after upload. Archive only after verifying the uploaded report, notebook, figures, and graph assets.

No license has been selected for the author's new code and writing. The dataset and bundled third-party visualization libraries retain their own terms and attribution. If reuse permissions are desired, select a suitable repository license before archiving.
